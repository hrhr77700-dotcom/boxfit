# BoxFit

물건 하나의 크기와 포장 여유로 알맞은 택배 박스를 추천하는 한국어 정적 웹사이트입니다.

## 실행 방법

**`index.html` 하나만 다운로드하고 더블클릭해서 브라우저에서 여세요.** CSS, JavaScript, 박스 데이터가 모두 HTML에 포함되어 있어 다른 파일, 설치, 빌드, 서버가 필요하지 않습니다. 모바일 화면도 지원하며 로그인, 결제, 외부 API 및 외부 폰트를 사용하지 않습니다.

1. 가로·세로·높이를 cm 단위로 입력합니다. 소수를 허용합니다.
2. 포장 여유를 선택합니다. 기본값은 2 cm입니다.
3. **맞는 박스 찾기**를 누르면 내부 부피가 작은 순서로 최대 3개를 표시합니다.
4. **예시 입력**은 20 × 15 × 10 cm, 여유 2 cm로 즉시 추천합니다. **초기화**는 물건 입력과 결과를 처음으로 돌리며 내 박스는 유지합니다.
5. **내 박스 추가하기**를 누르면 입력창이 열립니다. 이름(최대 60자)과 안쪽 가로·세로·높이를 입력하고 **박스 저장**을 누르면 창이 닫히고 저장 완료 안내와 함께 목록·추천 후보에 추가됩니다. **취소**, **×**, **Escape**로 저장하지 않고 닫을 수 있습니다. 소수 cm도 허용하며, 입력한 내부 크기에 포장 여유를 더하지 않습니다. 여유는 기존처럼 물건 치수에만 더합니다.
6. 추천 결과의 **예시 박스 / 내 박스** 표시로 출처를 구분합니다. 둘을 합쳐 부피가 작은 순서로 최대 3개를 추천하므로, 추가한 모든 박스가 결과에 표시되지는 않습니다. 내 박스를 추가하거나 삭제하면 이미 조회한 결과도 갱신됩니다.
7. **내 박스만 보기**를 선택하면 저장한 박스만 대상으로 작은 순서로 최대 3개를 추천합니다. 예시 규격과 판매 상품은 숨깁니다. 저장한 박스가 없으면 추가 버튼을, 맞는 박스가 없으면 전체 보기 버튼을 표시합니다.
8. 전체 추천에서 **1장만 구매**를 선택하면 판매 단위가 1장인 상품만 보여줍니다. 예시 규격과 내 박스에는 적용하지 않습니다. 맞는 1장 상품은 없지만 묶음 상품은 있으면 **묶음 상품 보기**로 전환할 수 있습니다.
9. 각 추천 카드의 **물건을 넣고 남는 공간**은 표시된 배치 방향에 따라 `박스 내부 치수 − 물건 치수`로 계산합니다. 각 축의 양쪽을 합한 값이며 선택한 포장 여유를 포함합니다. 예를 들어 27 × 18 × 15 cm 박스에 20 × 15 × 10 cm 물건을 넣으면 7 / 3 / 5 cm가 남습니다. 한쪽 여유나 완충재 두께를 뜻하지 않습니다.

추천을 조회한 뒤 필터를 바꾸면 결과가 즉시 갱신됩니다. 초기화는 필터도 **전체 / 모든 판매 단위**로 되돌리며 저장한 내 박스는 유지합니다.

여유는 각 치수에 총합으로 한 번 더합니다. 20 × 15 × 10 cm에 여유 2 cm를 선택하면 필요한 내부 크기는 22 × 17 × 12 cm입니다. 여섯 가지 직각 회전을 검사합니다. 대각선 배치, 물건 변형 및 여러 물건의 동시 포장은 계산하지 않습니다.

결과에는 박스 내부 가로 × 세로 × 높이, 부피(cm³), 원래 물건의 배치 방향 및 축 대응을 표시합니다. 맞는 박스가 없으면 필요한 최소 내부 크기를 안내합니다.

**‘예시 박스’로 표시한 추천 박스는 기능 확인용 예시 규격입니다. 실제 판매 상품이나 우체국 규격이 아닙니다.** ‘내 박스’는 사용자가 입력한 내부 규격입니다. 안쪽 크기가 맞는 박스가 판매 상품은 별도 추천 목록에서 판매 단위와 상품 링크를 표시합니다.

## 내 박스 보관

내 박스는 가능한 경우 브라우저의 localStorage에 저장됩니다. 같은 브라우저와 파일 위치에서 다시 열 때 불러올 수 있지만, `file://` 저장 방식은 브라우저마다 다릅니다. 파일을 옮기거나 브라우저를 바꾸면 목록이 달라질 수 있으며 목록은 다운로드한 HTML 자체에 기록되지 않습니다. 저장이 차단되어도 현재 창에서 추가·추천·삭제가 동작하고, 새로고침 시 사라진다는 안내를 표시합니다. 삭제 버튼으로 잘못 추가한 박스를 제거할 수 있습니다.

배포용 `index.html`은 외부 파일을 읽지 않습니다. 박스 규격은 HTML 내부의 `BOXFIT_BOXES` 목록(`[이름, 가로, 세로, 높이]`)에서 수정할 수 있습니다. 분리된 CSS·JS 파일은 개발용 원본으로 남겨두었습니다. 원본 변경 시 HTML에 포함된 내용도 함께 갱신해야 합니다. fetch와 JavaScript 모듈을 사용하지 않습니다.

## 검증 방법

사이트 사용에는 Node.js가 필요하지 않습니다. 자동 테스트는 Node.js 18 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
node --test tests/*.test.cjs
```

브라우저에서 확인할 예:

- 회전: 10 × 20 × 15, 여유 0 → 첫 추천 컴팩트(20 × 15 × 10), 물건 세로·높이·가로 순으로 배치.
- 딱 맞음: 예시 입력 → 필요 크기 22 × 17 × 12, 첫 추천 데일리.
- 너무 큼: 100 × 90 × 80, 여유 2 → 추천 없음, 필요 크기 102 × 92 × 82 안내.
- 잘못된 입력: 빈 값, 0, 음수, 문자 → 한국어 오류 안내.
- 소수: 19.5 × 14.5 × 9.5, 여유 2 → 소수 크기를 유지해 계산.
- 내 박스: 이름 `내 택배 박스`, 내부 크기 21 × 16 × 11 추가 → 물건 9 × 19 × 14, 여유 2에서 회전해 딱 맞으며 첫 추천에 ‘내 박스’ 표시. 여유 3으로 바꾸면 해당 박스는 제외됩니다.
- 1장 구매: 예시 입력 후 선택 → 판매 상품은 3호 1장만 표시. 물건 45 × 35 × 30, 여유 2에서는 맞는 1장 상품이 없고, ‘묶음 상품 보기’로 5호 3장 상품을 확인할 수 있습니다.
- 내 박스만: 물건이 작아도 예시 박스에 밀려 제외되지 않고 내 박스에서만 상위 3개를 고릅니다. 마지막 내 박스를 삭제하면 빈 목록 안내로 즉시 바뀝니다.
- 남는 공간: 물건 10 × 20 × 15, 여유 2 → 2호 박스에 회전해 넣으면 가로 7 / 세로 3 / 높이 5 cm가 남습니다.

Playwright와 Chromium이 설치된 환경에서 `node tests/recommendation-filters.browser.cjs`로 새 필터 흐름을 확인할 수 있습니다. 필요하면 `BOXFIT_BROWSER_PATH`를 지정합니다. 이 테스트는 외부 요청 없이 테스트 주소에 단독 HTML을 제공하며, 실제 `file://` 저장 동작을 검증하는 것은 아닙니다.

외부 공개 배포는 수행하지 않았습니다.

### 단일 HTML 검증 결과

HTML 안에 모든 스타일·데이터·스크립트가 포함되어 있고 개발용 원본과 일치하는지 자동 검사합니다. Chromium에 HTML 전체를 직접 로드하여 서버·외부 요청 없이 PC·모바일 추천, 회전, 딱 맞음, 크기 초과, 오류 안내, 소수, 예시 입력과 초기화를 확인했습니다. JavaScript 오류와 가로 넘침은 없었습니다. 클라우드 브라우저 정책이 `file://` 접근을 차단하여 실제 더블클릭 방식 자체는 직접 검증하지 못했습니다.

이전 버전은 사용자가 PC에서 직접 파일을 열어 추천 동작을 확인했습니다. 내 박스 기능을 추가한 현재 버전도 외부 파일 없이 구성되며, 새 다운로드용 HTML은 저장소 `index.html`과 바이트 단위로 동일합니다.

현재 버전은 자동 테스트 17개를 통과했습니다. Chromium에서 단일 HTML 내용을 직접 로드해 추가·삭제·추천 갱신, 출처 표시, 회전·여유, 잘못된 입력, 특수문자 이름, 모바일 320/375px을 검증했고 외부 요청과 JavaScript 오류는 없었습니다. 브라우저 내부에서 응답을 제공하는 테스트 주소(실제 서버 없음)에서는 localStorage 저장·새로고침·삭제·손상 데이터·저장 실패를 검증했습니다. 현재 버전의 실제 `file://` 열기는 관리자 정책으로 차단되어 직접 검증하지 못했습니다.

### 내 박스 입력창 확인

기존 버전의 ‘내 박스 추가하기’는 이미 화면에 보이는 입력 폼의 제출 버튼이었습니다. 현재는 입력창을 여는 버튼과 ‘박스 저장’ 버튼을 분리했습니다. 저장 시 입력이 잘못됐으면 창 안에 오류가 표시됩니다. 정상 저장하면 목록과 추천 후보에 추가되며, 물건 크기가 이미 유효하게 입력되어 있으면 추천도 바로 갱신합니다.

1. `index.html` 하나만 다운로드해 브라우저에서 엽니다.
2. ‘내 박스 추가하기’를 눌러 입력창을 엽니다.
3. 이름 `내 택배 박스 30`, 안쪽 크기 `30 × 25 × 20`을 입력하고 ‘박스 저장’을 누릅니다.
4. 목록에 해당 박스와 저장 완료 안내가 나타나는지 확인합니다.
5. 물건 `18 × 28 × 23`, 여유 `2 cm`로 추천하면 내 박스가 회전 배치 `28 × 23 × 18`로 추천됩니다. 부피는 `15,000 cm³`입니다. 동일 크기의 예시 박스도 함께 나올 수 있습니다.

Playwright와 Chromium이 있는 개발 환경에서는 `node tests/custom-dialog.browser.cjs`로 위 흐름을 검증할 수 있습니다. 필요하면 `BOXFIT_BROWSER_PATH`로 Chromium 실행 경로를 지정합니다. 이 도구들은 사이트 사용에는 필요하지 않습니다. 테스트는 먼저 HTML만 있는 임시 폴더의 `file://` 주소를 엽니다. 관리자 정책으로 차단된 경우 그 사실을 출력하고 HTML 직접 로드 방식으로만 기능을 검증하므로, 대체 검증 성공을 실제 파일 열기 성공으로 취급하지 않습니다.

현재 검증에서 30 × 25 × 20cm 박스의 입력창·저장·목록·회전 추천·여유 초과 제외, 취소·Escape·입력 오류, 모바일 화면이 통과했습니다. `file://` 직접 열기는 여전히 클라우드 관리자 정책으로 차단되어 직접 검증하지 못했습니다.

### 이번 복구의 검증 범위

main의 PR #1 병합 상태를 기준으로, 원격 feat/boxfit-standalone의 내 박스 기능을 재사용했습니다. 예시 입력은 requestSubmit에 의존하지 않고 추천 함수를 호출합니다. 저장 쓰기 후 읽기 값을 확인하며, 저장 실패 여부와 관계없이 현재 화면의 박스를 추천에 사용합니다. 완료 안내는 목록 추가와 영구 저장을 구분합니다.

`node --test tests/*.test.cjs`: 17개 통과. `node tests/custom-dialog.browser.cjs`: HTML 직접 로드에서 PC·모바일 입력창/추가/회전/추천/삭제 및 필요 크기 22 × 17 × 12 확인. 서버 없이 브라우저에서 응답을 제공한 테스트 주소에서 테스트 박스 30 × 25 × 20의 즉시 추가, 물건 28 × 23 × 18 + 여유 2에서 추천, 새로고침 후 복원, 저장 쓰기 차단 후 현재 창 박스 추천을 확인했습니다.

실제 file:// 접근은 클라우드 Chromium 관리자 정책의 ERR_BLOCKED_BY_ADMINISTRATOR로 차단되었습니다. 따라서 파일 직접 실행·파일 재열기 저장 유지·Windows Edge 동작은 이번 환경에서 검증하지 못했습니다. 대체 로드의 성공으로 해당 검증을 완료했다고 간주하지 않습니다. Windows에서 보고된 버튼 무응답의 정확한 원인은 아직 재현되지 않았습니다.


### 첫 완성본 정리 및 검증

물건 입력 → 추천 결과 → 내 박스 목록 순서로 배치했습니다. 예시 데이터의 결과에는 ‘예시 규격’을 표시하며, 저장 차단 시 ‘현재 창에서만 유지됩니다’를 표시합니다. 전체 후보와 상위 3개 표시를 분리해, 상위 3개 밖의 내 박스도 추천 후보인지 테스트합니다.
